Intelligent Work Routing Engine: explainable AI triage for Marketplace tickets

The current build gets the data right, but every attribute has the same weight. Status, priority, queue and confidence all show up as gray pills, and the AI's reasoning is printed as raw Matched keywords […] text. So an analyst can't tell at a glance what the AI decided, how sure it was, or why it fell short. This redesign makes each request card a one-line decision record. A colored rail plus an icon badge gives the outcome. A confidence meter with a visible 75% threshold shows how close the call was. A plain-English rationale with keyword and missing-field chips gives the reason. The human action sits next to the evidence. Human decisions use a distinct slate "person" treatment, AI decisions use green and amber, and anything mocked carries a striped SIMULATED ribbon that can't be mistaken for a real state. The palette stays restrained (one #464feb accent plus semantic colors), density can be adjusted, and every state is encoded twice (color + icon/shape/text). The result reads as calm, auditable enterprise software that a judge can follow in three minutes.

02 · High-fidelity

Dashboard / Inbox & Exception Queue: interactive prototype

Everything below works. Switch tabs, open a card, Approve, Override (with Undo), change density, search, and ingest a sample email. All 60 requests are generated synthetic data.

Jump to:

Explainability Outcome is encoded 3 ways

  • Left rail: solid green (AI routed), dashed amber (held), slate (human).
  • Badge: icon + words, never color alone.
  • Meter: solid vs hatched fill, plus "−5 pts below threshold" text.

Explainability Why it fell short

  • The rationale is a plain-English sentence, built from the same evidence as the score.
  • Keyword chips show what matched. Dashed amber chips show what's missing.
  • Score math is additive and auditable: 95 (strong match) − 25 (1 missing field) = 70.

Trust Human-in-the-loop is visible

  • Human decisions get a person glyph + slate color + "by A. Analyst".
  • Any decision, including auto-routed ones, can be overridden from the detail panel.
  • Every action can be undone for 6 s and is written to the audit trail.

08 · Assumptions & open questions

Assumptions

  1. Approve creates a 4th display state. The pipeline has three statuses, but a human-approved exception isn't the same as an AI auto-route, so it renders as Approved (green routed rail + person glyph, code HUMAN_APPROVED). This keeps "who decided" honest.
  2. Auto-routed = AI recommendation, already dispatched. The brief describes it as "just needs human approval". The demo treats it as dispatched-but-overridable, so the inbox doesn't require a second click on 44 items. If explicit sign-off is required, add a bulk "Confirm all auto-routed" action to the All tab.
  3. Confidence is shown as an additive, explainable score (keyword-match strength 65 / 80 / 95 for 1 / 2 / 3+ keywords, −25 per missing required field). This reproduces every value in the current screenshots (40, 55, 70, 80, 95). If the production model is ML, keep the waterfall UI and swap the factor labels for feature attributions.
  4. KPI definitions: Accuracy = agreement with a human-labeled evaluation set (58/60 = 96.7%). Minutes saved = 7 min of manual triage per auto-routed ticket (44 × 7 = 308).
  5. Threshold is global and read-only (75%). A threshold slider is a strong demo moment but was left out to keep scope tight.
  6. Branding: neutral wordmark and palette, with no bank logos or brand marks. Apply official brand assets only per brand guidelines and approval. "OneApproval" is generalized to "request approval".
  7. Data: all IDs, names ("A. Analyst"), systems ("…-SYN") and addresses (example.com) are synthetic.
  8. Out of scope: fulfillment/provisioning screens, auth/roles, settings, analytics drill-downs.
